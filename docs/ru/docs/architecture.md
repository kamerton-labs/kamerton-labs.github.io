# Устройство

Коротко о том, как Kamerton устроен внутри. Подробное описание пакетов, API и решений — в [ARCHITECTURE.md](https://github.com/kamerton-labs/kamerton/blob/main/docs/ARCHITECTURE.md) в репозитории (на английском).

## Одна программа

Kamerton — одна программа на Go. Она отдаёт HTTP API и веб-интерфейс (React, встроен в программу) и запускает контроллер Kubernetes. Программы наблюдения ставятся рядом как зависимости Helm-чарта.

```
описание системы (ресурс SystemDescription или файл)
   │
   ├─► проверка: JSON Schema и смысловые проверки
   ├─► генерация: правила Prometheus, панель Grafana,
   │              маршруты Alertmanager, заготовки инструкций
   ├─► применение: PrometheusRule, AlertmanagerConfig, ConfigMap
   │               (server-side apply)
   └─► постоянная сверка: контроллер следит за SystemDescription
                          и пишет условия в статус
```

## Как проходит сигнал

1. Сервис отправляет телеметрию в OpenTelemetry Collector.
2. Collector раскладывает её по хранилищам: метрики в Prometheus, логи в Loki, трассы в Tempo. По трассам он считает число запросов, ошибок и время ответа.
3. Prometheus проверяет правила, которые создал Kamerton. Когда условие держится дольше заданного времени, правило срабатывает.
4. Alertmanager отправляет сообщение по маршруту из описания системы.
5. Дежурный получает сообщение: что случилось, в каком сервисе, текущее значение и порог, время в своём часовом поясе, ссылку на инструкцию.

| Часть | Что делает |
| --- | --- |
| OpenTelemetry Collector | Принимает метрики, логи и трассы, считает по трассам запросы, ошибки и время ответа |
| Prometheus | Хранит метрики и каждые 15 секунд проверяет правила |
| Loki | Хранит логи |
| Tempo | Хранит трассы |
| Grafana | Показывает графики, логи и трассы, переход от трассы к логам по `trace_id` |
| Alertmanager | Отправляет оповещения в Telegram и на почту, склеивает повторы |
| Kamerton | Ставит всё это одной командой, превращает описание в правила, маршруты и инструкции, показывает это в интерфейсе |

## Источник правды

- **Описание в YAML — источник правды.** Интерфейс только редактирует его: схема, карточки правил и режим YAML меняют один и тот же текст.
- **Схема описания выводится из типов Go.** Из них получаются CRD и JSON Schema; одна и та же схема проверяет описания в ядре и даёт подсказки в редакторе YAML.

## Что ещё делает ядро

- **Обнаружение.** Показывает сервисы, которые уже присылают телеметрию, по метрикам из трасс в Prometheus.
- **Проверка на истории.** Считает, сколько раз правило сработало бы на данных Prometheus.
- **Вероятный источник.** Когда срабатывает оповещение, проходит по связям `dependsOn` и показывает цепочку затронутых сервисов.
- **Наборы программ.** Каждая система читает Prometheus и Alertmanager своего набора; метки набора ставятся на её PrometheusRule и AlertmanagerConfig.

## Удаление объектов

Объекты системы ссылаются на её `SystemDescription`, поэтому при удалении системы удаляются все её объекты. Объект, который система перестала создавать, пока остаётся до удаления самой системы.

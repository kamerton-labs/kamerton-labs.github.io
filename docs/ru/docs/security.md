# Безопасность

## Сначала включите вход

Сразу после установки интерфейс и API открыты всем, кто может до них достучаться. Пока вход выключен, любой, кто открыл интерфейс, может заменить или удалить токен бота, изменить получателей и отправлять сообщения от имени бота. Сами токен и пароль не возвращает ни один запрос API.

Открывайте интерфейс без входа только через `kubectl port-forward` или прокси с проверкой подлинности.

## Как устроен вход

- Один общий логин и пароль из переменных `KAMERTON_AUTH_USER` и `KAMERTON_AUTH_PASSWORD`. В Kubernetes они берутся из Secret (`auth.existingSecret`, ключи `username`, `password` и по желанию `session-secret`) и никогда не попадают в ConfigMap или аннотацию. Локально — из файла `.env`.
- Если задана только одна из двух переменных, ядро не запустится.
- При включённом входе все запросы `/api/*`, кроме `/healthz`, `/api/v1/health` и `/api/auth/*`, требуют сессию.
- Сессия — cookie HttpOnly с подписью HMAC-SHA256, действует 12 часов. Ключ подписи — `KAMERTON_AUTH_SECRET` (ключ `session-secret` в Secret), а без него — производный от пароля, поэтому смена пароля завершает все сессии.
- После пяти неудачных попыток за минуту с одного адреса вход с него блокируется до конца минуты (ответ 429).

```sh
kubectl -n kamerton create secret generic kamerton-auth \
  --from-literal=username=admin --from-literal=password='<надёжный пароль>'
helm upgrade kamerton ./deploy/helm/kamerton -n kamerton --reuse-values \
  --set auth.existingSecret=kamerton-auth
```

## Заголовок X-Requested-With

Запросы, которые что-то меняют, должны нести заголовок `X-Requested-With`. Интерфейс ставит его сам. Чужой сайт не может отправить такой запрос из браузера без разрешения, поэтому заголовок защищает от подделки запросов с чужих сайтов. Если вы обращаетесь к API из своих скриптов, добавляйте заголовок к изменяющим запросам.

## HTTPS

Без HTTPS пароль передаётся открытым текстом. Включите TLS на ingress. Cookie сессии помечается Secure, когда ingress ставит заголовок `X-Forwarded-Proto: https`.

## Где хранятся секреты

Секреты не попадают ни в описание системы, ни в values чарта, ни в репозиторий.

| Что | Где |
| --- | --- |
| Токен бота Telegram | Secret `kamerton-telegram`, ключ `bot-token`, в пространстве имён Kamerton |
| Пароль SMTP | Secret `kamerton-smtp`, ключ `password` |
| Логин и пароль входа | Secret из `auth.existingSecret` или созданный чартом |
| Пароль администратора Grafana | Secret `kamerton-grafana`, его создаёт чарт Grafana |

В ConfigMap ничего секретного нет: `kamerton-telegram-state` (имя бота, чаты, состояние опроса), `kamerton-email-state` (сервер, отправитель, логин), `kamerton-stacks` (адреса и метки наборов программ).

Токен отправляется только в Bot API Telegram. Ошибки соединения, в которых есть адрес запроса с токеном, очищаются, прежде чем попасть в логи или ответы. Ядро читает Secret с токеном прямыми запросами; права RBAC — чтение и изменение одного этого Secret по имени и создание Secret в пространстве имён (Kubernetes не умеет ограничить создание по имени), без list и watch.

## Ссылки на Secret

Alertmanager отправляет значение Secret, на который ссылается получатель, на адрес этого получателя: пароль SMTP уходит на `smarthost`. Если бы описание могло ссылаться на любой Secret, через него можно было бы отправить чужой секрет на свой сервер. Поэтому описание, сохранённое через API или интерфейс, может ссылаться на Secret только в трёх случаях:

1. Получатель Telegram ссылается на Secret токена самого Kamerton в его пространстве имён.
2. Получатель почты ссылается на Secret SMTP самого Kamerton вместе с почтовым сервером и логином, настроенными в Kamerton. Другой `smarthost` отклоняется.
3. В сохранённой версии той же системы уже была точно такая же ссылка (для почты — с тем же `smarthost` и логином). Так описания, которые администратор кластера применил через kubectl, остаются редактируемыми в интерфейсе.

Всё остальное отклоняется с ошибкой 400 `secret_not_allowed`; проверка и предпросмотр описания сообщают ту же ошибку. Через API описания создаются только в пространстве имён Kamerton (или в единственном наблюдаемом), иначе 400 `namespace_not_allowed`. `runbookURL` и `--external-url` должны быть абсолютными адресами http или https.

## Что вход не умеет

- Один общий пользователь: нет ролей и журнала действий по пользователям.
- Счётчик попыток входа хранится в памяти каждой реплики и считает адрес TCP-соединения, поэтому за ingress он общий для всех клиентов.

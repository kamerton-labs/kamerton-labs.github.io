# Оповещения

Оповещения отправляет Alertmanager по маршрутам, которые Kamerton создаёт из описания системы. Каналы — Telegram и почта. Их удобнее всего подключить в интерфейсе, на экране «Каналы»; Telegram и почта настраиваются из интерфейса только в кластере.

Каналы общие для всех систем. Что каждая система отправляет в какой чат или на какой адрес, выбирается внутри системы: на схеме, в блоке «Куда отправлять оповещения».

## Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и вставьте токен на экране «Каналы». Ядро проверит токен запросом `getMe` и сохранит его в Secret `kamerton-telegram` (ключ `bot-token`) в пространстве имён Kamerton. Токен не попадает ни в описание, ни в логи, ни в ответы API; интерфейс показывает только имя бота. Если Secret с этим именем уже есть, он продолжает работать.
2. Добавьте бота в группы. Ядро опрашивает Telegram и через несколько секунд показывает чаты. Чат, из которого бота удалили, помечается недоступным. Если группа стала супергруппой, Kamerton переходит на её новый ID, в том числе в получателях в описании.
3. Отправьте тестовое сообщение, выберите для чата важность (и при желании сервисы) и сохраните. Получатели и маршруты записываются в описание системы, контроллер пересоздаёт AlertmanagerConfig.

**Ограничения Telegram.** Telegram хранит обновления 24 часа и не умеет выдавать список чатов бота. Поэтому чат, куда бота добавили задолго до запуска Kamerton, сам не появится: проверьте его по ID на том же экране или добавьте бота заново. У бота может быть только один получатель обновлений и не должно быть webhook — заведите для Kamerton отдельного бота.

## Почта

1. Подключите почтовый сервер: SMTP `host:port` (есть подсказки для Яндекса, Mail.ru и Gmail), адрес отправителя, логин и пароль. Ядро проверит вход на сервер и сохранит пароль в Secret `kamerton-smtp` (ключ `password`). Сервер, отправитель и логин хранятся в ConfigMap `kamerton-email-state`. Пароль не попадает ни в описание, ни в логи, ни в ответы API.
2. Добавьте получателей: название и один или несколько адресов, например «Дежурные» с двумя адресами. Тестовое письмо проверит доставку.
3. В системе «Куда отправлять оповещения» → «Добавить получателя» предлагает и чаты Telegram, и получателей почты.

Если потом поменять сервер или адреса получателя, Kamerton обновит все системы, которые его используют.

::: warning Почта проверена только на тестовом сервере
Отправка почты проверена на тестовом SMTP-сервере, не у реального почтового провайдера.
:::

## Получатели и маршруты в описании

То, что настроено в интерфейсе, записывается в описание в обычном виде. Получателей можно писать и вручную — они продолжают работать и не меняются интерфейсом.

```yaml
notifications:
  receivers:
    - name: oncall-telegram
      telegram:
        chatID: -1001234567890            # замените своим
        botTokenSecret: {name: kamerton-telegram, key: bot-token}
    - name: team-email
      email:
        to: [oncall@example.com]
        from: kamerton@example.com
        smarthost: smtp.example.com:587
        authUsername: kamerton@example.com
        authPasswordSecret: {name: kamerton-smtp, key: password}
  routing:
    critical: [oncall-telegram, team-email]
    warning: [team-email]
    groupBy: [alertname, service]   # по умолчанию
    repeatInterval: 4h              # по умолчанию
    routes:
      - receiver: team-email
        severities: [critical]
        services: [payment]
  language: ru
  timeZone: Asia/Almaty
```

- `critical`, `warning` — получатели оповещений всех сервисов с этой важностью.
- `routes` — получатель только для перечисленных сервисов (и, если указано, только этой важности).
- `groupBy` — какие метки склеивают оповещения в одно сообщение.
- `repeatInterval` — как часто повторять сообщение о том, что ещё не прошло.

Описания, которые отправляют оповещения, должны лежать в пространстве имён Kamerton. Какие ссылки на Secret допустимы и почему — в разделе [Безопасность](./security#ссылки-на-secret).

## Что в сообщении

Kamerton использует свои шаблоны сообщений для Telegram и почты вместо шаблонов Alertmanager по умолчанию. В сообщении:

- проблема или решено, важность, система и окружение;
- для каждого оповещения — сервис, что не так, текущее значение и порог, с какого времени;
- ссылки на страницу оповещения и инструкцию в интерфейсе, если задан `externalURL`.

Сгруппированные оповещения идут компактным списком: не больше 8, дальше их число.

## Язык и часовой пояс

Сообщения по умолчанию на русском; `spec.notifications.language: en` переключает их и описания оповещений на английский.

Время по умолчанию в UTC. Другой пояс задаётся в `spec.notifications.timeZone` именем IANA, например `Asia/Almaty` или `Europe/Berlin`, или на схеме, в блоке «Куда отправлять оповещения». Время пишется со сдвигом: «09:18 16.11 UTC+5».

Kamerton сам вычисляет сдвиги по базе часовых поясов, встроенной в программу, включая переходы на летнее время, поэтому пояс работает, даже если в образе Alertmanager его нет.

## Свои тексты

У любого правила может быть свой текст оповещения на любом языке: заголовок, пояснение и первое действие для дежурного. В интерфейсе он задаётся в карточке правила, в блоке «Текст оповещения», с предпросмотром.

```yaml
errorRate:
  threshold: 0.01
  message:
    title: Оплата не проходит
    text: Ошибок {value} при пороге {threshold} в {service}, с {since}
    action: Проверьте платёжный шлюз и последние выкладки
```

Подстановки — фиксированный список:

| Подстановка | Что подставляется |
| --- | --- |
| `{value}` | текущее значение |
| `{threshold}` | порог |
| `{service}` | сервис |
| `{operation}` | операция; пусто, если правило не про одну операцию |
| `{system}` | система |
| `{since}` | когда началось |

Другие фигурные скобки и любая разметка отклоняются проверкой описания: текст показывается так, как написан. Значения экранируются.

Где лежит текст: `message` у правил ошибок, задержки, остановки запросов, очереди, SLO и у своих правил; `memoryMessage`, `cpuMessage`, `oomKilledMessage`, `restartsMessage` у правил ресурсов; `consumerStoppedMessage` у правила «очередь перестали читать».
